# 1.1 — Sessions (save & reopen a whole piece)

Status: **tracked for 1.1, not started.** 1.0 is feature-frozen. Board task #116
(the "sharing/format" item — sessions are its core; the portability bundle is the wrapper).

## The problem

You can already **export** a finished piece to a DAW (the #98 session BOUNCE: stems + MIDI +
manifest, one-way). What you can't do is **come back to the piece inside synth and keep working.**

Today a **MULTI** is the closest thing to a project file, and it already restores a lot:

- every part's patch / kit / edited sound, per-part FX + 3 LFOs, mixer level/pan,
- surface routing + split zones, the step-sequencer patterns, scene configuration, tempo.

**What a MULTI does NOT save — the gap that loses your work:**

- the **recorded looper content**: each lane's recorded **MIDI clip** (`Looper::Lane` is an
  in-memory `std::array<Event>` with no serialisation), and the **audio-loop buffers** (the
  audio you recorded into the AUDIO lanes — big ring buffers, never persisted);
- the **per-scene captured loop clips** (scenes snapshot lane clips in RAM only).

So reopen a MULTI and your sounds/routing/patterns are back, but **the loops you played are
gone.** Sessions close that: reopen exactly where you left off.

## Goal

A **Session** = the full working state of a piece, saved to one place and reopened intact:
everything a MULTI holds **plus** all recorded looper content (MIDI + audio) and scene clips,
so nothing you performed is lost.

## Format — a session bundle (folder or `.vasynthproj` zip)

A single XML can't hold the audio (up to ~98 MB of loop buffers), so a session is a **bundle**:

```
mypiece.vasynthproj/            (a folder, or a zip with this layout)
  session.xml                   MULTI + all global params + looper MIDI clips + scene clips + tempo
  audio/lane1.flac … lane4.flac recorded AUDIO-lane buffers (FLAC = lossless + compact)
  samples/…                     kit-pad samples referenced by the parts (via SampleStore md5)
  manifest.json                 format version, BPM, created/modified, app version+hash
```

This is **the same artefact as the #116 portability bundle** — a session that carries its own
audio + samples *is* portable by construction. One format, two uses (reopen locally / hand to
another machine). `.vasynthkit` embedding (samples-in-kit) is the kit-scoped slice of the same
idea.

## What to build

1. **Looper MIDI-clip serialisation (highest value, smallest).** Add `Looper::Lane` ↔ ValueTree
   (events as a compact child list or base64 blob) and fold it into the MULTI/session save+load.
   This alone recovers the MIDI loops — most of the felt loss — with no bundle needed yet.
2. **Audio-loop persistence.** Write each non-empty AUDIO lane to `audio/laneN.flac` on save;
   restore into the ring on load (respecting `kMaxLoopSeconds`). Only touched when a lane has
   audio, so MIDI-only pieces stay tiny.
3. **Scene clips.** Serialise the per-scene captured lane clips with the scene block.
4. **Bundle container + samples.** Wrap the above + the referenced SampleStore samples into the
   `.vasynthproj` bundle (folder first; zip optional). This is the #116 portability payload.
5. **File menu + UX.** New / Open Session / Save / Save As / **Recent sessions**; a dirty-state
   indicator ("• unsaved"); and an **autosave / crash-recovery** file so a crash doesn't cost the
   piece (write a rolling autosave to the data dir; offer to restore on next launch).

## Design questions to resolve at build

- **Audio compression:** FLAC (lossless, ~50 % of raw, JUCE has a codec) vs raw WAV (simplest,
  bigger). Recommend FLAC.
- **Folder vs zip:** a folder bundle is simplest to write/inspect and diff-friendly; a zip is one
  tidy file to hand off. Ship folder first, zip as a later convenience.
- **Backward compatibility:** a session must open across app versions — `manifest.json` carries a
  format version; loaders migrate older layouts (the MULTI loader already has v1→v2 migration
  precedent).
- **Determinism:** MIDI clips + params reload bit-identically (goldens); audio is compared by
  decoded PCM equality after a FLAC round-trip.
- **Size honesty:** surface the bundle size on save (a 4-lane full-audio piece is tens of MB);
  MIDI-only pieces are kilobytes.

## Tests

- Record MIDI loops on all four lanes + capture two scenes → save session → **reload → the loops
  and scene clips come back sample-accurate** (MIDI golden; scene clips identical).
- An AUDIO-lane recording survives save→load through the FLAC round-trip (decoded-PCM equality).
- A session saved on Linux opens on Windows identically (cross-platform determinism goldens).
- Autosave writes on a timer and the recovery prompt restores it; a normal clean quit clears it.

## Build order
1. Looper MIDI-clip serialisation into MULTI (recovers MIDI loops — do first, biggest felt win).
2. Scene clips.
3. Audio-loop FLAC persistence + the `.vasynthproj` bundle (folder).
4. Samples-in-bundle (= the #116 portability payload) + zip container.
5. File menu, Recent, autosave/crash-recovery.

Each increment independently gated (`run-all-checks.sh` ± `--sanitize`, goldens, CI green).
Feature is additive — existing MULTIs still load (a MULTI is a session with no audio/clips).
